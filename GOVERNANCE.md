# Governance

Panodash uses a maintainer-led, contribution-friendly model.

Maintainers set roadmap priorities, review changes, manage releases and security reports, and protect the project's privacy principles and package boundaries. Routine decisions are made through pull-request review. Significant architecture, governance, data-use, or compatibility changes should begin with a public issue and allow reasonable time for community input.

Consensus is preferred. When consensus is not available, the active maintainers decide based on user safety, privacy, maintainability, and project direction. Maintainers must disclose relevant conflicts of interest and should recuse themselves when another qualified maintainer can decide.

New maintainers are invited based on sustained, constructive contributions and sound judgment. Maintainer access may be removed for inactivity, security needs, or conduct violations. The current maintainers are represented by `.github/CODEOWNERS` and repository access controls.
